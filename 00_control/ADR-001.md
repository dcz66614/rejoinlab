# ADR-001：报告路径终态 `fullPath` / `resumePath` 改为 `PathResult | null`（SPEC_VERSION 1.0.0 → 1.0.1）

- 日期：2026-11-23
- 提出：终审 R1 P1-R1-03（P031 FIX-R1 B 组）
- 决定：采纳（规格修订，保留实现的诚实行为）
- 状态：已冻结进规格 v1.0.1；代码实施见 FIX-R1 B 组（schema.ts、测试回归）

## 问题（P1-R1-03）

PROJECT_BOOK.md v1.0.0 §13.2 把 `fullPath` / `resumePath` 写为必填
`PathResult` 对象；但生产实现（`src/replay/planner.ts` 的
`evaluateFixture`）在没有双轨终态时返回 null（`src/report/schema.ts`
第 163–166 行类型已是 `ReportPathResult | null`，JSON Schema 亦接受
null）。终审 R1 认定这是规格与实现冲突的 P1，必须修订规格，不得反向
要求实现伪造路径。

实现返回 null 的分支（`src/replay/planner.ts`，逐行核对）：

| 分支 | 位置 | 裁决 | fullPath | resumePath |
|---|---|---|---|---|
| 事件数超限（>40） | 第 1188–1189 行 | INCONCLUSIVE_LIMIT | null | null |
| 未知 / 不支持事件类型 | 第 1214–1215 行 | INVALID_INPUT | null | null |
| 完整折叠或检查点解析抛错 | 第 1244–1245 行 | INVALID_INPUT | null | null |
| 恢复折叠抛错 | 第 1278–1279 行 | INVALID_INPUT | 对象 | null |
| 正常完成双轨折叠 | 第 1320–1321 行 | 由分类决定 | 对象 | 对象 |

关键事实：null 是**按路径独立**的，不是按裁决一刀切的。恢复折叠失败时
fullPath 有对象而 resumePath 为 null；BFS 节点超限的 INCONCLUSIVE_LIMIT
（`src/replay/search.ts` 的 `analyzeFixture`）仍带已算出的双轨终态，路径
照常为对象。因此“某裁决 ⇒ 两路径必为 null”是错误的读法；null 与对象
按实际计算结果取舍。

## 决定

PROJECT_BOOK.md §13.2 修订为（规格 v1.0.1）：

```ts
fullPath: PathResult | null;
resumePath: PathResult | null;
shortestInjectionSequence: string[] | null;
```

语义：
- null 表示“本次分析没有该路径的终态”，绝不伪造一条空路径。
- 允许 null 的情形见上表：输入无效（INVALID_INPUT）与事件数超限
  （INCONCLUSIVE_LIMIT）。BFS 节点超限仍带已算出终态，不属此列。
- 消费者（JSON 报告组装、HTML 导出、UI 对照、时间线）不得把 null
  误读为 CONSISTENT 的证据：null 只出现在 verdict 为 INVALID_INPUT
  或 INCONCLUSIVE_LIMIT 的报告中，且 verdict 本身才是裁决依据；
  各消费者均有显式 null 分支（`src/report/json.ts` 的 `toReportPath`
  原样透传 null；`src/report/html.ts` 的 `pathSection` 渲染“无终态”；
  `src/ui/StateDiff.tsx` 的 `PathSummary` 渲染“无终态”；
  `src/ui/Timeline.tsx` 渲染“（无）”；`src/ui/App.tsx` 以可选链取
  runStatus），见 tests/report/fix-r1-null-paths.test.ts 的运行时证据。

## 为什么 null 比伪造空路径诚实

一条伪造的空 PathResult 必须带一个 `finalStateHash`。任何填入的哈希要么
是某个真实状态的哈希（与本次计算无关，误导复核者去比对一个不存在的
终态），要么是空对象的 canon 哈希（暗示“终态就是空状态”，而实际是
“根本没有算出终态”）。两种填法都把“未知”伪装成“已知”，且一旦写入报告
就无法与真正的空终态区分。null 在类型、JSON Schema 与 UI 上都是显式
的“缺失”，复核者一眼可辨，且与 §7“INCOMPLETE_TRACE 不得降级为
CONSISTENT”的诚实边界一致。

## 备选方案（已否决）

- B：伪造空 PathResult（空 messages / 空 toolCalls / 空 sharedState +
  空状态哈希）。否决：见上节，伪造数据不可与真实空终态区分，破坏报告
  的可复核性。
- C：把 fullPath / resumePath 改为可选字段（缺失即无终态）。否决：
  缺失与 null 在 JSON 中含义相近，但现有 JSON Schema 要求两字段必填
  （`required` 含 fullPath / resumePath），且 `null` 在 TypeScript 类型
  与校验器中都是显式、可断言的值；改为可选会扩大三处改动面（类型、
  Schema、校验器）而无额外表达力。
- D：维持 §13.2 不变，要求实现在无效输入时仍算出终态。否决：未知事件
  无法折叠，超限输入按 §8.1 不得继续计算；强行计算违反规格自身的边界。

- 测试：tests/report/fix-r1-null-paths.test.ts 新增回归——INVALID_INPUT
  双 null、INCONCLUSIVE_LIMIT 双 null、非对称 null（仅 resumePath）、
  null 路径报告仍通过 Schema 校验、消费者（JSON 序列化 / HTML 渲染）
  不把 null 误认为 CONSISTENT。

  Golden 预期。R2 终审复核本 ADR（null 情形是否穷尽、消费者分支是否
  真实存在）。
